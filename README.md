# autopolyphonic

Animusic-style stage of procedurally built instruments that will perform MIDI files. every instrument is generated in code, and its dimensions come from the notes it plays. C++17, SDL2, OpenGL 3.3 core profile

## build and run

needs SDL2 and a C++17 compiler. glad (the OpenGL loader) and glm are bundled in `third_party/`, so there's no GLEW or anything else to install.

- Linux: `sudo apt install g++ make libsdl2-dev libgl-dev`
- macOS: `brew install sdl2`
- Windows: MSYS2/MinGW with the `SDL2` package

```sh
make
./autopolyphonic
```

run via the project folder so it finds `shaders/`

## controls

| input | action |
|---|---|
| left or middle drag | orbit |
| shift + drag, or right drag | pan |
| ctrl + drag, scroll wheel, PgUp/PgDn | zoom |
| arrows | orbit in 5 degree steps |
| `=` / `-` | field of view |
| `0` | reset camera |
| `w` | wireframe |
| `n` | normals view |
| `m` | show the shadow depth map |
| esc | quit |

on launch, a built-in metronome plays the stage (stand in for MIDI). the ride swings on every beat, the kick and snare alternate, and the marimba bars bounce one at a time up the keyboard

## what

- **no model files**
  - everything is built at startup by some geometry tools: a lathe, polygon extrusion with ear-clipping caps, and a path sweep with mitered joints
  - the lathe and extrusion tools use crease-angle normals. the same tool gives sharp edges and smooth curves
- **pitch-based geometry**
  - marimba (52 bars, A2 to C7): bar length scales as 1/sqrt(f), like a real free bar
  - its brass resonators are quarter-wave tubes, 343 / 4f long
  - the rails sit under each bar's vibration nodes (22.4% from each end), following a least-squares cubic fit so they run smooth
  - pipe organ (49 pipes, C2 to C6): each pipe is a half-wave open pipe, 343 / 2f long, so low C is 2.6 m. diameters halve every 16 semitones, a standard organ-builder scale
- **parametric drum kit**
  - one drum builder covers kick, snare and toms: shell, two heads, hoops, lugs and tension rods from a size spec
  - stands take any number of legs, and snare and cymbal stands tilt about a real pivot joint
  - every piece turns to face where the drummer's seat would be
- **shadow mapping in core profile,** a depth pass from the light into a framebuffer object, then hardware depth compares with linear filtering for softened edges
- **animation framework.** parts have a motion type (swing, bounce with wobble). `strike(channel, note, time)` sets one off, and each frame turns "time since the hit" into a damped-sine transform. channels work like MIDI channels (9 is drums) therefore MIDI playback should just work when implemented (AI-assisted)
- **intuitive camera controls** mimics blender (3d modeling program) controls -- drag to orbit, shift/right-drag to pan (the grabbed point stays under the cursor at any zoom), scroll or ctrl-drag to zoom. zoom is exponential, so a mouse wheel and a trackpad's tiny fractional scrolls feel the same. (AI-assisted)

## plan

- **textures:** my own PBR materials (wood, metal, drum stuff, velvet, etc), with texture coordinates generated by the lathe and extrusion tools
- **MIDI playback:** my own MIDI file parser, with sound from a SoundFont synthesizer (TinySoundFont) running in an SDL audio callback. the audio sample counter is the master clock, so every strike lands on its note
- **harp,** with string lengths that scale as 1/f
- **mallets and sticks** that swing into each strike, with some anticipation before the note
- **audit mode:** a piano-roll overlay. plus test MIDI files (scales, steady repeated notes, a simple song) for checking sync
- **spotlights** on active instruments. the camera shall also point at the most active instruments
